# LiftLoop — project rules

Single-user, mobile-first workout logger. Spec: `docs/superpowers/specs/2026-09-07-liftloop-design.md` (source of truth). Plans: `docs/superpowers/plans/`. Design mockups: `design/*.dc.html` (generated by `node design/build.mjs`).

## Commands

- `pnpm dev` — Next dev server (uses PGlite in `./.pglite` when `DATABASE_URL` is unset)
- `pnpm test` — Vitest (domain logic + DB tests on in-memory PGlite)
- `pnpm typecheck` — `tsc --noEmit`
- `pnpm build` — `next build` (pure; the pre-commit hook runs this)
- `pnpm db:generate` — drizzle-kit migration from `src/db/schema.ts`; `pnpm db:migrate`; `pnpm db:seed` (idempotent upsert, never touches the loop pointer); `pnpm db:reset` (wipe local PGlite + migrate + seed)

## Structure

- `src/lib/domain/` — pure training logic (parser, phase, goal, verdict, PRs, report). No DB, no `Date.now()`; callers pass `todayIST`.
- `src/db/` — Drizzle schema, client (PGlite locally / Neon serverless Pool in prod), migrations in `drizzle/`, seed in `src/db/seed/program-v2.ts`.
- `src/actions/` — server actions (Zod-validated). `src/db/queries/` — read helpers.
- `src/lib/queue/` — client FIFO write queue for set logs (localStorage `liftloop.queue.v1`).
- `src/app/(auth)/login`, `src/app/(app)/*` — screens; `src/proxy.ts` — auth proxy (Next 16 name for middleware).

## Naming

- User-facing: "sign in" (never "log in"); "session" = a gym session; the auth cookie is `ll_session` (never call it a session in UI copy).
- Code: `delete`/`restore` for soft deletes; `logSet`/`finishSession`/`startSession`; `formatLoad` for every load string.

## Architecture map

| Question | Where |
|---|---|
| Where is a goal computed? | `src/lib/domain/goal.ts`, called from `src/actions/session.ts#startSession` (server-side, snapshot stored in `session_exercise.goal`) |
| Where do reads filter deleted rows? | every query in `src/db/queries/*` uses `isNull(deletedAt)`; `session_exercise` inherits from its session |
| Where is "today"? | `src/lib/domain/time.ts#todayIST` (Asia/Kolkata) — never `new Date()` date math elsewhere |
| Where is the rest timer's duration? | `template_exercise.rest_seconds ?? exercise.rest_seconds` via `session_exercise.template_exercise_id` |
| Where does the queue live / drain? | `src/lib/queue/runner.ts`, mounted by `QueueRunner` in `src/app/(app)/layout.tsx` |

## Errors and logging

Server actions throw `AppError` from `src/lib/errors.ts` (code + message); the client shows the message in a toast. Unexpected errors log to the server console with context (session id, exercise id) and surface as "Something went wrong".

## Failure log

- A global git pre-commit hook (`~/.git-hooks`) runs `pnpm run build` on every commit. Stop `next dev` before committing if the build ever corrupts `.next`.
- `~/.npmrc` pins `before=2026-05-06`: `pnpm add` of anything published later fails with "no matching version". Don't remove the pin; pick an older version.
- Vitest 5 needs `vite` as a dev dependency (peer), otherwise `vitest run` fails to start.
- `.pglite/` (local DB) must stay gitignored — it is personal data.
- `src/lib/env.ts` imports `server-only`; scripts run under `tsx` (`src/db/*.ts`) must read `process.env` directly instead.
- `getDb()` must stay cached on `globalThis` (not module scope): Next dev evaluates `src/db/client.ts` once per bundle, and two PGlite instances on the same `.pglite/` dir see different data and then abort with `RuntimeError: Aborted()`. Symptom seen: `/api/backup` returned zero sessions while pages showed them (2026-09-07). If `.pglite/` ever aborts, `pnpm db:reset`.
- Never build a date string like `YYYY-MM-31`: Postgres rejects it (September calendar 500, 2026-09-07). Compute the real last day.
- Sonner toasts sit exactly where a bottom sheet's primary button lands on a 390 px phone; dismiss toasts (`toast.dismiss()`) before opening the check-in sheet and scroll targets to centre in QA scripts.
- PGlite must be in `serverExternalPackages` (next.config.ts) or its wasm loader breaks under Turbopack bundling.
- Do not add `export type { … }` to a `'use server'` module — Next's action bundler fails with "Export … doesn't exist in target module"; import types from the query module instead.
