# LiftLoop Phase 3 (v1.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v1.1 (spec §5.2, §14 Phase 3): progress screens (per-exercise charts, weekly sets per muscle, adherence heatmap), in-app program + gym-config editor with seed protection, service-worker offline for the session screen, optional token export endpoint.

**Architecture:** Charts are client components (Recharts 3.8.1) fed by server queries in `src/db/queries/progress.ts`; token colours are read from the theme at runtime. The editor is a set of Zod-validated server actions over the existing tables plus one additive migration (`edited_at` columns, `default_*` on exercise, `archived` on template_exercise); the seed skips edited rows. Offline is a network-first cache of the last session/home HTML in the existing service worker.

**Tech Stack:** unchanged + `recharts@3.8.1` (published 2026-03-25, before the pin; 5M+ weekly downloads).

**Spec:** `docs/superpowers/specs/2026-09-07-liftloop-design.md` — §5.2, §6.4, §7.6, §7.7, §10.3, §14.

### Task P3-1: Token export endpoint

**Files:** `src/app/api/coach-export/route.ts`, `src/proxy.ts` (public path), `src/lib/env.ts` (`COACH_EXPORT_TOKEN` optional ≥ 32), `.env.example`, README.
