# LiftLoop Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete v1 (spec §14 Phase 2): Body screen, Home menu actions (walk day, different template, easy week, discard), session swap + "type it instead" + PR badges + wake lock, History calendar + editing, Exercise detail, notes import, JSON backup/restore, PWA, Share, More screens, polish.

**Architecture:** Same as Phase 1. New server actions stay Zod-validated and throw `AppError`; new pure logic (import planning, backup shape) lives in `src/lib/domain/` with Vitest. Finished-session edits use the same rev-guarded `logSet`/`deleteSet` actions directly (no queue: the queue is for the in-progress session only, spec §11.2).

**Tech Stack:** unchanged. New dev-only: none. New runtime: none (service worker is hand-written).

**Spec:** `docs/superpowers/specs/2026-09-07-liftloop-design.md` — §5.1, §5.3, §6.2, §6.3, §6.4–6.7, §11.4, §14.

### Task P2-2: Home menu actions — walk day, different template, easy week, discard

**Files:** `src/actions/program.ts` (`startEasyWeek(today)`, `endEasyWeek(today)`), `src/actions/session.ts` (`logWalk({ date, minutes, note })`, existing `discardSession`/`undoDiscard`), `src/components/home/home-menu.tsx` (client sheet from the "…" button), `src/components/home/walk-sheet.tsx`, `src/components/home/template-picker.tsx`, tests in `src/db/__tests__/program-actions.test.ts`.

Behaviour (§6.2, §2.1, §2.2): "Start a different template" → picker of the 6 templates, then a confirm "Advance the loop as if this was the next one?" (Yes default / No) → `startSession({ id, templateId, advancesLoop })`. "Log a walk day" → sheet: minutes (default 20), note → creates a finished `walk` session dated today (`advancedLoop = false`). "Start easy week now" → appends `{ from: today, to: weekEnd(today) }` to `easy_week_overrides` (extends an active override instead of duplicating); during a manual easy week the item reads "End easy week" → sets that override's `to` to yesterday (or removes it if it started today). Discard on Home → `discardSession` with an undo toast (`undoDiscard`).

- [ ] Tests: walk never advances; easy-week start/end shape; `getPhase(today)` flips to Easy manual. Commit `feat(home): walk day, different template, easy-week override, discard`.

Behaviour (§6.3): **swap** → sheet listing `slot.swapOptions` → `swapExercise` → replace slot `{ exercise, goal, sets: [], collapsed: null, swappedFrom }` (server returns goal; refetch the view via `router.refresh` is not needed: build the new slot from the action result + option name). Gate: disabled while `runner.pendingFor(session) > 0`. **type it instead** → one-line input under the rows; Enter → `logSetsFromShorthand` → replace the slot's sets from `rows` (status saved), collapsed from `exerciseDone`; errors inline. Gate on pending too. **PR badge**: logged row shows a small `PR` chip when `isPr` (server-confirmed). **Wake lock**: `navigator.wakeLock.request('screen')` on mount, re-request on `visibilitychange` → visible, release on unmount; ignore errors.

### Task P2-6: Notes-text import (§5.3)

**Files:** `src/lib/domain/import-plan.ts` (+ test), `src/actions/import.ts`, `src/app/(app)/more/import/page.tsx`, `src/components/import/import-view.tsx`.

**Interfaces:**
```ts
// pure
planImport(text, exercises, assignedDate): { blocks: PlannedBlock[]; errors: ParseError[]; skippedLines: number }
PlannedBlock = { rawName; exerciseId: string | null; lo; hi; sets; unilateralMarker; lines: { date: string; segments: ParsedSegment[]; keep: boolean }[] }
// only the last two lines of each block have keep=true; most recent = assignedDate, older = assignedDate − 7 (§5.3); report re-import: text between "## Sessions" and the next "## " only; "### YYYY-MM-DD …" sets the default date (and template name) for the following blocks.
groupByDate(blocks) → { date: string; templateName: string | null; entries: { exerciseId; lo; hi; sets; segments }[] }[]
// action
importNotes({ groups }) → { created: number } — one imported session per date (source 'imported', started_at = finished_at = 12:00 IST, advanced_loop false, note 'Imported from notes'), session_exercise per entry (goal null, lo/hi/sets from the header, order_index = position), set_logs (unit from exercise, rev 1). Refuses (AppError CONFLICT) any date that already has a live session. Recomputes PRs for touched exercises.
```
UI (§6.7): textarea → Preview: per block the resolved name (or a select to map / skip), the kept lines with editable dates, errors listed; Save.

- [ ] Tests: the §3 example plans 7 blocks × 2 lines with dates D and D−7; report paste keeps only the Sessions section; conflict on an existing date. Commit `feat(import): notes-text import`.
