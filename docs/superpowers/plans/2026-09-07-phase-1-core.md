# LiftLoop Phase 1 (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship LiftLoop Phase 1: passcode auth, seeded program DB, Home, goal-first session logging with a durable write queue, History list + detail, and the coach markdown export — tested, pushed to `main`, ready for Vercel.

**Architecture:** Next.js 16 App Router. All training rules live as pure, Vitest-covered functions in `src/lib/domain/` and are called from Server Actions / Server Components. Drizzle over PGlite locally (file-backed, no Docker) and over Neon's serverless Pool in production, sharing one migration set. The session screen is a client component fed by server data; every set write goes through a single FIFO localStorage queue with `rev`-guarded upserts.

**Tech Stack:** Next 16.2.4, React 19, TypeScript strict, Tailwind 4, shadcn/ui (base-nova), Drizzle ORM 0.45 + drizzle-kit, `@electric-sql/pglite` (dev/test), `@neondatabase/serverless` (prod), `jose`, `zod` 4, `date-fns` 4 + `@date-fns/tz`, Vitest 4, `tsx`, `puppeteer-core` (QA shots only).

**Spec:** `docs/superpowers/specs/2026-09-07-liftloop-design.md` — every task below cites its section. Read the cited sections before starting a task; the spec is the authority on copy, rules and edge cases.

## Global Constraints

- pnpm only. Never remove the machine's `~/.npmrc` `before=2026-05-06` pin; `pnpm add` resolves to versions before that date. Pin exact versions (`save-exact=true` is already set).
- TypeScript `strict`; no `any`, no `@ts-ignore` without a one-line WHY. `pnpm typecheck` and `pnpm build` must pass before every commit (a global pre-commit hook runs `pnpm run build`; stop any `next dev` before committing).
- Every date/"today"/"this week" computation goes through `src/lib/domain/time.ts` with `Asia/Kolkata`; never `new Date().getDay()` or server local time (spec §1, §7.10).
- All loads render through `formatLoad` (§4.3). All colours through theme tokens in `globals.css` (no `bg-gray-950` style literals).
- Every read of sessions/sets filters `deleted_at IS NULL` (§9 "Live").
- Domain functions are pure: no DB, no `Date.now()` — the caller passes `todayIST`.
- Commit after every task with a conventional message; push after every task (`git push origin main`). Never `--no-verify`.
- Copy in the UI is exactly the spec's copy (goal lines §7.4, next notes §7.5, banner §2.3, nudge §6.2).
- New dependencies must be checked (`npm view <pkg> time --json`) to exist before the pin date; report each new dep in the task's commit body: name, version, why.
